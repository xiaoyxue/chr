# Component responsibilities

**Status:** `draft` — 总体分工为 `confirmed`；下表更细的预览、持久化等分工为 `proposed`。

**Scope:** 功能级的操作、配置、执行和反馈归属，不定义进程布局或消息格式。

**Depends on:** [System architecture](system-architecture.md)、[Business workflow](business-workflow.md)。

## Responsibility boundaries

总体分工以架构文档为准。区分用户操作入口、业务配置和实时执行，
不因某功能“在 WebUI 可操作”就认为它只需前端实现。
候选原则：需要本地文件或进程能力的控制功能由 Local Server 承担；
纯编辑/查看可留在控制侧；影响实际输出的修改应有执行结果反馈。
配置持久化位置、运行中状态的权威来源和多入口控制仲裁尚未确定。

## Responsibility matrix

| Feature | Control side | Runtime side | Open boundary |
| --- | --- | --- | --- |
| 球场与本地数据选择 | 读取和展示本地数据，组织选择。 | 获得渲染所需配置。 | 本地目录和数据导入格式。 |
| 广告位信息管理 | 管理素材关联、布置和编辑。 | 准备并使用当前运行配置。 | 方案版本、保存和激活方式。 |
| 虚拟场地粗定位 | 编辑位置，提供虚拟场地视图。 | 是否提供共用预览能力待定。 | 不预设浏览器与实时侧共用同一渲染实现。 |
| 扫描录制与编码 | 发起、停止和查看进度，定位输出文件。 | 组织 SDI 采集、录制与编码任务。 | 高清晰标准、编码实现和素材交付。 |
| 离线建模接入 | 发起 create、查询结果并选择要 load 的记录。 | 协调当前机位标定与 tracking 上下文；渲染核心不必加载 atlas。 | 参考图/Ti 对与 C 是公共产物，算法资源属于内部细节。 |
| 球场标定坐标系微调 | 提供交互编辑和结果比较。 | 在实际输出中应用相应修正。 | 修正表示、保存位置和作用范围。 |
| 广告位模型位置微调 | 操作和保存布置调整。 | 更新实例变换并反馈结果。 | 与粗定位是否使用同一配置层。 |
| 广告位开关 | 提供单项/组合操作入口，组合范围待定。 | 执行实际显隐。 | 生效时刻、失败和确认语义。 |
| 实时追踪接入 | 选择运行配置，呈现追踪状态。 | 将实时视频交给追踪服务，关联当帧图像、Ti 与相容 C。 | 首期 pinhole；输入/结果协议、帧关联和超时行为待细化。 |
| 帧输入与渲染 | 配置运行上下文，呈现任务及资源状态。 | 维护 scene，解耦画面写入与渲染提交，管理资源就绪和复用。 | 帧池实现、提交边界和具体方法见帧输入设计。 |
| 光照控制 | 编辑和预览参数。 | 将适用于直播的光照设置用于实际渲染。 | 光源种类、材质响应与控制范围。 |
| 广告位透明度 | 提供参数编辑。 | 执行实际透明度/混合行为。 | 实例、材质或分组作用域与颜色语义。 |
| 模型、视频与动画 | 提供素材选择与播放控制，具体范围待定。 | 运行时加载与播放，支持能力待定。 | 素材标准、播放时钟和结束行为。 |
| 虚拟 3D 视角 preview | 交互查看场地、相机和内容。 | 是否提供离屏视图或媒体流待定。 | 需要复现什么效果、计算发生在哪一侧。 |
| 实际合成画面预览 | 展示实际效果及状态。 | 负责实际视频合成；预览输出方式待定。 | 预览来源、协议及其与真实输出的对应关系。 |
| 直播视频输入输出 | 展示设备与运行状态，提供配置入口。 | 组织采集、渲染合成与输出；内部帧调度方式待定。 | 硬件接口、时间、颜色、音频及附属数据。 |
| 可选输入/输出录制 | 提供录制操作与文件管理。 | 组织录制任务，视频链路复用方式待定。 | 与准备期扫描录制分别定义质量和资源约束。 |

## Interface handoff

每项跨模块功能都需要回答：谁发起、谁执行、修改哪个对象、何时生效、
如何确认成功、如何报告失败、结果是否保存，以及重连后如何恢复认知。

具体方法承接这些答案，沿用 [Protocol conventions](protocol-conventions.md)
和 [Execution model](execution-model.md)，不在每个功能中重复定义通用规则。
