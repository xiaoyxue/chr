## 第一层：业务范围与系统边界

已确认：

- Fusion 是历史 Public Web Server，首期抽象掉，先支持本地数据。
- chr 初期交付 WebUI + Local Server，以及可独立运行的实时渲染 CLI/服务。
- 四个讨论模块为控制 WebUI、实时渲染服务、离线场景建模、实时追踪服务。
- 两个分析模块的实现可能在仓库外，chr 负责录制准备、实时视频供给和结果接入等相关接口。
- 主要用户界面是 WebUI，CLI 可辅助操作。
- 控制侧负责业务配置和操作；实时渲染侧作为现场视频运行时，组织 SDI 采集、
  追踪接入、渲染合成、输出与录制任务，不要求这些工作处于同一线程。
- 抽象控制命令与 effect 不绑定发起者，允许 WebUI、CLI 或固定 trigger 发起。
- 实时处理允许有界延迟和批处理，但输出保持连续；25 帧/50 FPS 只是讨论示例。
- 主相机输入称为 Cam1 SDI 流；静态标定录制产物为 MP4 加配套逐帧元数据，整体交付。

## 第二层：模块行为与数据模型

在相关业务问题明确后逐项细化：

- 球场、布置方案、session、相机配置、校准结果的身份、版本与关联。
- 控制 WebUI/Local Server 与实时渲染服务的配置持久化、运行状态归属和多入口控制方式。
- 扫描任务的发起、采集、提交、进度、取消、结果接收与人工确认。
- Cam1 录制产物的组织、命令边界、最大时长及元数据范围，见 [录制讨论](recording-control.md)。
- 球场标定坐标系微调与广告位模型位置微调的分工、作用域和组合方式。
- 素材导入、支持能力检查、现场可用性、模型内部结构及动画片段的选择。
- 实例的创建、放置、显隐、替换、删除，以及是否需要组合和成组控制。
- 视频与动画的开始、暂停、恢复、循环、速率、结束行为和时间依据。
- 现场调整的作用对象、保存位置、撤销方式与跨 session 复用。
- 预览类型、状态反馈，以及如何确认操作已经影响实际输出。
- 控制失败、重复操作、断线重连、多客户端操作时的行为。

这些问题明确之前，不先声明最终命令名或 wire schema。

## 第三层：视频、渲染与接口技术

以下保留历史参考提出的问题，同时列出直接相关的接口议题：

| 主题 | 必须回答的问题 |
| --- | --- |
| SDI 时间 | 输入和输出的时间信息如何保留、关联？源时间、处理时间与输出时钟如何区分？ |
| 帧与缓存 | 采集卡交付的内容与可供渲染使用的图像缓存有什么差异？格式、所有权、就绪与释放怎样表达？ |
| 扫描模式 | 支持哪些分辨率、帧率和逐行/隔行格式？需要去隔行时由谁处理？ |
| 颜色 | 输入、渲染和输出采用什么像素格式、色域、传递函数、范围及转换？ |
| 合成边界 | 现场视频运行时内部如何组织渲染与合成？叠加层怎样表达，音频与附属数据如何处理？ |
| 同步与延迟 | 怎样关联视频、几何和动画时刻？延迟目标和超时行为是什么？ |
| 可选录制 | 是否录制输入/输出，如何保留关联与诊断信息，怎样避免影响播出？ |
| 部署与连接 | 在本地控制侧与渲染 CLI 的边界内怎样连接？素材与校准如何交付？分析模块怎样接入？ |
| 几何接口 | 明确坐标系、矩阵方向、SNC 图像域、相机模型及几何不可用的表达。 |
| 运行故障 | 输入丢失、渲染异常、进程或硬件失败分别如何处理？是否需要外部旁路？ |

技术选型应服务于这些行为约束，不用某个库“支持视频/渲染”的事实代替实际接口与时序分析。
